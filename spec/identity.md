# Личность: ключи, подписи, хранение

Детали к разделам `docs/spec.md` «Идентичность и ключи» и «Форматы данных».
Реализации: `server/pkg/identity` (Go) и `client/lib/core/identity`,
`client/lib/core/vault`, `client/lib/core/account` (Dart). Векторы:
`testdata/vectors/bip39` и `slip10` (официальные), `testdata/vectors/identity`
(свои, генерирует `make vectors`).

## Фраза → ключи

```
12 слов BIP39 (английский список, пароль BIP39 пустой)
  → seed = PBKDF2-HMAC-SHA512(фраза, "mnemonic", 2048 итераций)       64 байта
  → SLIP-0010, кривая ed25519: корень = HMAC-SHA512("ed25519 seed", seed)
  → m/22860'/0'/0'   главный ключ (seed Ed25519 = закрытая половина узла, 32 байта)
  → m/22860'/0'/1'   следующий главный ключ
  next_key_hash = SHA-256(открытый ключ узла m/22860'/0'/1')
```

- `22860'` = `0x594C`, ASCII «YL». Это не номер из BIP44 и SLIP-0044, поэтому
  ключи не пересекаются с кошельками, даже если те же слова вставить в кошелёк.
- `0'` — ветка «личность»; другие номера зарезервированы под другие семейства ключей.
- `i'` — поколение главного ключа: `0` — текущий, `1` — следующий (ротация во второй версии).
- Для ed25519 SLIP-0010 допускает только hardened-индексы; обычный индекс — ошибка.
- Ввод фразы нормализуется: нижний регистр, слова через один пробел. Слова списка —
  ASCII, поэтому NFKD из BIP39 ничего не меняет, а любой не-ASCII символ даёт
  ошибку «слово не из списка».
- Ошибки фразы: `word_count` (не 12/15/18/21/24 слова), `unknown_word` (с номером
  слова), `checksum`.

## Отпечаток

Первые 8 байт SHA-256 открытого ключа, четыре группы по 4 hex-символа заглавными
через «·» (U+00B7): `2DEC·9955·D7E0·675A`. Короткий — первые две группы.
В интерфейсе — только через `redact(fingerprint, …)`.

## Подпись

`s = Ed25519(ключ, "yl-v1" | t | p)` — байты склеиваются без разделителя. Это
однозначно, пока ни один тип `t` не начинается с другого (проверяется тестом в
Go и Dart; новый тип должен сохранить это свойство). Ed25519 детерминирован
(RFC 8032), поэтому одна и та же подпись получается в Go и Dart.

Проверка конверта (`Verify` / `Signed.verify`): известный `t`, `k` — 32 байта,
подпись сходится, `p` — корректный по профилю CBOR словарь. Открытие типа
(`OpenProfile` / `openProfile` и т. д.) дополнительно проверяет поля и подписанта:

| Тип | Кто подписывает | Проверка подписанта |
| --- | --- | --- |
| `profile` | master | `k == profile.master` |
| `device_cert`, `revoke`, `devices` | master | `k ==` известный главный ключ |

Категории ошибок, общие для Go, Dart и векторов: `unknown_type`, `wrong_type`,
`bad_key`, `bad_signature`, `bad_payload`, `signer_mismatch`.

## Поля

- Текст (`name`, `about`, `reason`, имя устройства, `banner_color`) подписывается в
  каноническом виде: Unicode NFC, без пробелов Unicode White_Space по краям.
  Длина — в кодовых точках. Управляющие символы (C0, DEL, C1) запрещены; в
  `about` разрешён только перевод строки.
  Обрезка — ровно по набору White_Space, как `unicode.IsSpace` в Go (`String.trim`
  в Dart срезает ещё и U+FEFF, поэтому в Dart своя обрезка).
- `name` 1–32, `about` 0–300, имя устройства 1–64, `reason` 0–200 символов.
- `banner_color` — имя токена `banner-1…banner-5`; неизвестное имя показывается
  как `banner-1` (проверяется только как текст, чтобы старые клиенты читали новые цвета).
- `wall` при создании профиля — `true`.
- `seq` профиля начинается с 1. `updated`, `created`, `at` — unix-время, мс.
- Аватар: квадрат 256×256, PNG, ≤ 512 КБ, `{sha256, mime: "image/png", size}`.
- `platform` в `device_cert`: `windows` | `linux` | `android` | `macos`.
- Имя устройства по умолчанию не содержит имени компьютера (оно уходит на
  серверы и часто содержит настоящее имя): «Компьютер · Linux», «Телефон · Pixel 8».
- Неизвестные поля payload при разборе игнорируются; байты `p` хранятся как есть.

## Хранение на устройстве

| Что | Где |
| --- | --- |
| Энтропия фразы под PIN (блоб `YLM1`) | системное хранилище, ключ `yl.master.v1` |
| Seed ключа устройства (32 байта) | системное хранилище, `yl.device.v1` |
| Счётчик неверных PIN | системное хранилище, `yl.pin_guard.v1` |
| Подписанные профиль и сертификат устройства, аватар | папка приложения, не секрет |

Системное хранилище: Android Keystore, Диспетчер учётных данных Windows (записи
защищены DPAPI; одна запись ≤ 2560 байт), libsecret на Linux. Для тестов —
`MemoryVault`, для отладки в Docker — `FileVault` (`--dart-define=YL_VAULT=file`,
только debug, без шифрования).

Хранится энтропия, а не главный ключ: по ней восстанавливается и фраза для показа
после PIN, и главный ключ. Главный ключ держится в памяти только на время подписи.

### Блоб `YLM1`

```
"YLM1" | secret u8 | kdf u8 | memory_kib u32 | iterations u32 | parallelism u8
       | salt 16 | nonce 24 | XChaCha20-Poly1305(key, энтропия) + tag 16
secret: 1 — PIN, 2 — пароль (фаза 7, «длинный пароль вместо PIN»)
kdf:    1 — Argon2id
key = Argon2id(секрет, salt, memory_kib, iterations, parallelism) → 32 байта
AAD = "yl-master-v1" | master_pub | весь заголовок до шифротекста
```

Целые — big-endian. Параметры KDF лежат в блобе и защищены AAD, поэтому их можно
менять без миграции. Неверный секрет и повреждённый блоб неразличимы.

Параметры: основные — 64 МиБ, t = 3, p = 1; запасные — 19 МиБ, t = 2, p = 1
(минимум OWASP). При создании клиент прогоняет запасные и по их времени оценивает
основные (×5,05); если оценка больше 1,5 с — берёт запасные.

PIN — 6 цифр. Первые 5 ошибок без паузы, дальше 30 с, 1 мин, 2 мин … до часа;
ключ не стирается. Это защита интерфейса от подбора руками; от офлайн-перебора
защищают системное хранилище и Argon2id (PIN из 6 цифр — всего 10⁶ вариантов).

## Восстановление по фразе

Создаются новый ключ устройства и `device_cert`. Профиль и список `devices`
(с текущим `seq`) новое устройство получает с сервера — фаза 2.
