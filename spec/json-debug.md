# Отладочный JSON

Сервер с флагом `--codec=json` говорит тем же кадром в JSON, а утилита `yl-decode`
переводит CBOR-кадры из логов в тот же вид. Это не отдельная сериализация структур,
а представление модели данных CBOR — поэтому перевод однозначный в обе стороны,
и внутри сервер и клиент всегда работают с CBOR.

| CBOR | JSON |
| --- | --- |
| `null`, `true`, `false` | `null`, `true`, `false` |
| целое | число без точки и экспоненты: `42`, `-7` |
| float64 | число с точкой или экспонентой: `1.0`, `0.1`, `1e+300` |
| текст | строка |
| байты | `{"$bytes": "<base64url без =>"}` |
| массив | массив |
| словарь (ключи — текст) | объект; ключи выводятся в порядке CBOR |

Ограничения:

- `NaN` и бесконечности в JSON непредставимы — ошибка `json`.
- Словарь с единственным ключом `$bytes` неотличим от байтов — ошибка `json`.
- Повтор ключа в объекте — ошибка `dup_key`, целое вне int64 — `int_range`,
  вложенность глубже 16 — `depth`: те же правила, что у CBOR.
- `yl-decode --hex` показывает байты как `{"$hex": "…"}` — это только для чтения
  человеком, обратно такой JSON не принимается.

Пример — событие `challenge`:

```json
{
  "d": {
    "ts": 1790000000000,
    "nonce": { "$bytes": "KfsJfzlADYu5eo3Q3G3pzBs9MG_M2779EKdkT3auruA" },
    "server_pub": { "$bytes": "Ehv22FcSmI81KzkrfVvI5OE3uWf6B5aQvQWc6MwyUp0" }
  },
  "op": "challenge"
}
```
